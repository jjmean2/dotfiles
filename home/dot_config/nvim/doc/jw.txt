==============================================================================
목차								*jw* *jw-keys*

이 파일은 dotfiles 가 설치한 설정(nvim, tmux, lazygit)에서 내가 정한 키 배치와
익히려는 순정 키를 모아 둔 개인 치트시트다. 플러그인 문서가 아니라 "내 배치" 의
문서다. 여는 법: <leader>? 또는 :h jw. tmux 에서는 prefix H.

  1. 지금 익히는 키		|jw-learning|
  2. nvim 순정			|jw-nvim|
  3. 피커 (snacks.picker)	|jw-picker|
  4. git			|jw-git|
  5. tmux			|jw-tmux|
  6. lazygit			|jw-lazygit|
  7. 이 파일 고치기		|jw-edit|

원칙: 순정 키는 지우거나 뜻을 바꾸지 않는다. 추가 키는 <leader>(스페이스) 아래
네임스페이스에 둔다. 어떤 키가 어디서 왔는지는 :verbose map <키>.

1. 지금 익히는 키						*jw-learning*

손에 붙을 때까지 이 절만 본다. 붙으면 아래 절로 내리고 다음 묶음을 올린다.

Claude 가 고친 것 검토하기 (가장 자주 하는 일) ~
	]h  [h		다음/이전 hunk 로
	<leader>ghp	이 hunk 가 뭘 바꿨나 (인라인 미리보기)
	<leader>ghs	이 hunk 스테이징		비주얼이면 선택한 줄만
	<leader>ghr	이 hunk 되돌리기		비주얼이면 선택한 줄만
	<leader>ghd	파일 전체를 index 와 나란히 (순정 diff 모드, |jw-diff|)

파일 찾기와 검색 ~
	<leader><leader>	파일 (Cmd+P). 입력창에서 시작
	<leader>fg		내용 grep. Ctrl-q 로 전부 quickfix 에 → :copen → ]q
	Ctrl-^			직전 파일로 (순정)

코드 (순정 LSP 키) ~
	Ctrl-]  Ctrl-T	정의로 / 돌아오기		K  문서
	grr		참조 목록 (quickfix)		gO  현재 파일 심볼 목록
	grn  gra	이름 변경 / 코드 액션		]d [d  진단 이동

git 전체 ~
	<leader>gg	lazygit (nvim 안)		prefix G  lazygit (tmux 팝업)

도움말 ~
	<leader>?	이 파일				<leader>fk  키맵 검색

2. nvim 순정							*jw-nvim*

전부 플러그인 없이 되는 것들이다. :h default-mappings, :h lsp-defaults.

LSP (서버가 붙으면 자동) ~
	K		호버 문서
	Ctrl-]		정의로 (tagfunc)		Ctrl-T  태그 스택 되돌아오기
	grr		참조 → quickfix		gri  구현	grt  타입 정의
	grn		이름 변경			gra  코드 액션
	gO		문서 심볼 → location list
	Ctrl-X Ctrl-O	insert 모드 수동 완성 (omnifunc)	i_Ctrl-S  시그니처

자동완성 ('autocomplete', 플러그인 없음) ~
	타이핑하면 팝업이 뜬다. LSP 후보가 먼저, 버퍼 단어가 뒤에.
	Ctrl-N  Ctrl-P	항목 이동			Ctrl-Y  확정 (스니펫/import 적용)
	Ctrl-E		팝업 닫기			Enter  는 평소대로 줄바꿈 (noselect)
	Tab		스니펫 안에서 다음 자리		<leader>th  inlay hint 토글
	조절은 lua/config/core/options.lua 의 자동완성 블록 한 곳에서 한다:
	  너무 자주 뜬다 → autocompletedelay 올리기 (ms)
	  버퍼 단어가 LSP 후보를 가린다 → complete 의 .^5 w^5 b^5 숫자를 줄이거나 빼기
	  엉뚱한 fuzzy 항목이 올라온다 → completeopt 에서 fuzzy 빼기
	  아예 끄려면 :set noautocomplete (수동 Ctrl-X Ctrl-O 는 그대로)
	피커 입력창에서는 꺼져 있다 (core/autocmds.lua). 팝업이 떠 있으면 snacks 가 듣는
	TextChangedI 가 발생하지 않아 live grep 갱신이 멈추기 때문.
	gq		LSP 포맷 (formatexpr). 저장 시 포맷은 conform, 수동은 <leader>cf

진단 ~
	]d  [d		다음/이전 진단		Ctrl-W d  현재 줄 진단 자세히
	<leader>fd	현재 파일 진단 피커

quickfix / location list (|jw-quickfix|) ~				*jw-quickfix*
	:copen :cclose	quickfix 창			:lopen :lclose  location list
	]q  [q		다음/이전 항목		[Q  ]Q  처음/끝
	:cdo {cmd}	각 항목에서 실행 (예: :cdo s/old/new/g | update)
	:colder		이전 목록 (최근 10개 보관)
	채우는 것: :grep (ripgrep), grr, 피커의 Ctrl-q, <leader>ghq

diff 모드 (|jw-diff|) ~							*jw-diff*
	]c  [c		변경 블록 이동 (diff 모드 안에서만 순정 그대로)
	do  dp		상대 창에서 가져오기 / 상대 창으로 보내기
	zo  zc		접힌 영역 열기/닫기
	:diffoff! | only	종료
	여는 법: <leader>ghd (index), <leader>ghD (HEAD). 순정으로는
	:vnew | r !git show :./# | windo diffthis

statusline (맨 아래 한 줄, 순정 포맷 문자열) ~
	경로 [+]  브랜치 +추가 ~변경 -삭제   ...   E에러 W경고  LSP이름  [형식] 줄:열 %
	창이 여러 개여도 하나만 (laststatus=3), 커서가 있는 창 기준. 수정: core/statusline.lua

그 밖에 ~
	gcc  gc{motion}	주석 토글			Ctrl-L  검색 하이라이트 해제
	Ctrl-^		직전 파일			:cd {dir}  프로젝트 루트 이동 (|jw-cwd|)
	:verbose map {키}	그 키가 어디서 정의됐나

cwd (|jw-cwd|) ~							*jw-cwd*
	전제: nvim 하나 = 프로젝트 하나 = cwd. 피커, :grep, :find, LSP 가 전부 cwd 를 본다.
	:pwd / :cd {dir} / :cd -	확인 / 이동 / 직전으로
	<leader>fp			최근 프로젝트 피커 (cwd 변경)
	nvim-tree 는 cwd 와 양방향 동기화돼 있다 (- 로 상위, Ctrl-] 로 루트 변경도 :cd).

3. 피커 (snacks.picker)						*jw-picker*

멘탈 모델: source(후보) → picker(좁히기) → action(열기/분할/quickfix). 피커는
quickfix 로 들어가는 입구이고, 결과를 쌓아 돌아다니는 건 여전히 quickfix 다.

	<leader>ff  <leader><leader>	파일				:find
	<leader>fg			내용 grep			:grep
	<leader>fb			버퍼				:ls
	<leader>f.			최근 파일			:oldfiles
	<leader>fr			LSP 참조			grr
	<leader>fs			현재 파일 심볼			gO
	<leader>fd			현재 파일 진단
	<leader>fc			명령어 (Cmd+Shift+P)		: + Tab
	<leader>fh			도움말				:h
	<leader>fk			키맵				:map
	<leader>fp			프로젝트 전환 (cwd)		:cd
	<leader>fR			마지막 피커 다시

시작 포커스 (picker.lua 의 sources) ~
	입력창(insert): 파일, grep, 도움말, 명령어, 키맵, 심볼	→ 바로 타이핑
	목록(노멀):	버퍼, 최근, 프로젝트, 참조, 진단, git	→ j/k 로 고르기

피커 안에서 ~
	목록 창	j k gg G 이동	Enter 열기	i 또는 /  입력창으로	q 닫기
	입력창	타이핑으로 좁히기	Ctrl-j/k 이동	Tab 여러 개 선택	Esc 노멀 모드
	Ctrl-v  Ctrl-s  Ctrl-t	세로 분할 / 가로 분할 / 탭으로 열기
	Ctrl-q			전부(또는 선택)를 quickfix 로
	alt-p  alt-h  alt-i	미리보기 토글 / 숨김 파일 / .gitignore 무시
	?			키 도움말

4. git								*jw-git*

세 층: hunk 조작(gitsigns, <leader>gh*) / 목록(피커, <leader>g*) / lazygit.
기준 차이: gitsigns 의 sign 과 ghd 는 index 기준(스테이징하면 사라짐),
<leader>gd 피커는 HEAD 기준(스테이징해도 남음).

hunk (gitsigns) ~
	]h  [h		다음/이전 hunk		]H  [H  마지막/첫 hunk
	<leader>ghs	스테이징 (x: 선택 줄)	<leader>ghr  되돌리기 (x: 선택 줄)
	<leader>ghu	스테이징 취소
	<leader>ghS	버퍼 전체 스테이징	<leader>ghR  버퍼 전체 되돌리기
	<leader>ghp	미리보기 (인라인)	<leader>ghP  미리보기 (플로팅)
	<leader>ghb	현재 줄 blame		<leader>ghB  버퍼 blame
	<leader>ghd	index 와 diff		<leader>ghD  HEAD 와 diff
	<leader>ghq	이 버퍼 hunk → quickfix	<leader>ghQ  모든 hunk → quickfix
	ih		hunk 텍스트 객체 (vih, dih, yih)
	<leader>tb	줄 끝 blame 토글

목록과 도구 ~
	<leader>gd	저장소 전체 hunk 피커. Tab 스테이징, Ctrl-r 되돌리기
	<leader>gs	git status 피커
	<leader>gl	커밋 로그 (lazygit)	<leader>gf  현재 파일 히스토리 (lazygit)
	<leader>gg	lazygit (nvim 안 플로팅). e 로 연 파일은 이 nvim 의 새 탭에
	<leader>gb	현재 줄 blame (ghb 와 같음)

5. tmux								*jw-tmux*

prefix 는 Ctrl-b (순정) 또는 Ctrl-a. 모든 tmux 조작은 prefix 로 시작하고, nvim 의
창 조작은 Ctrl-w 로 시작한다. 이 둘이 두 도구의 경계다.

	prefix %   "		좌우 / 상하 분할 (현재 디렉토리 유지)
	prefix o  방향키	패널 이동 (zoom 상태 유지)	prefix ;  직전 패널
	prefix z		이 패널만 전체 화면 토글
	prefix q		패널 번호 표시		prefix x  패널 닫기
	prefix c  n  p		윈도우(탭) 만들기 / 다음 / 이전
	prefix d		분리. tmux a 로 복귀	prefix s  세션 목록
	prefix w		세션/윈도우/패널 트리
	prefix [		복사 모드 (vi 키). q 로 나옴
	prefix ?		tmux 전체 바인딩 목록
	prefix G		lazygit 팝업
	prefix H		이 치트시트 팝업
	prefix S		프로젝트 → 세션 전환기 (없으면 만든다). 세션 = 프로젝트  (tmux-dev)
	prefix W		워크트리 → 윈도우 전환기 (없으면 만든다). 윈도우 = 워크트리 (tmux-dev)
	prefix :		명령 입력 (예: set -g popup-style 'bg=#2a2b3d')

tmux-dev: 세션 = 프로젝트, 윈도우 = 워크트리, 패널 = 역할 ~
	tmux 계층을 개발 계층에 대응시키는 확장 (~/.config/tmux/plugins/tmux-dev). tmux 의
	세션·윈도우를 대체하지 않고 얹는 관례라 prefix c 의 보통 윈도우, 저장소 아닌 세션,
	순정 tmux new 는 그대로다. "플러그인" 은 tmux.conf 의 run-shell 한 줄이 진입 스크립트
	(tmux-dev.tmux)를 돌리고 그 스크립트가 bind-key 를 부르는 것이 전부다. 키·팝업 크기·
	레이아웃은 @tmux-dev-* 옵션 (진입 스크립트 머리말). 파일은 XDG 에 종류별로:
	~/.config/tmux-dev/projects (목록), ~/.local/state/tmux-dev (최근), ~/.local/share/tmux-dev/
	worktrees (워크트리). 셸: tmux-dev project|worktree ... (--help).

세션 = 프로젝트 ~
	prefix S 로 프로젝트를 고르면 그 이름의 세션으로 간다. 처음이면 세션을 만들고
	왼쪽 셸(여기서 claude) / 오른쪽 nvim 으로 연다. 열린 세션끼리는 prefix s 로도 간다.
	셸에서: tmux-dev project [경로] [--layout ide|plain]. prefix d 로 분리해도 세션은 남는다.

	팝업 안 (헤더에도 적혀 있다). fzf 순정 키(ctrl-p/n 이동, ctrl-a/e 줄 처음/끝)는 그대로.
	tab / shift-tab		모드 순환: project(목록) → dir(파일시스템 검색) → recent(최근).
				검색어는 모드를 바꿔도 유지된다
	Enter			선택. 맞는 후보가 없으면 친 글자를 경로로 (팝업을 띄운 패널 기준)
	alt-enter		후보가 있어도 친 글자를 경로로. 없는 경로면 만들지 물어봄 (왼쪽 option)
	ctrl-t / ctrl-x / ctrl-o	커서 항목 등록 / 제거 / 목록 파일 열어 편집
	목록 파일: ~/.config/tmux-dev/projects (머신별, 형식은 파일 주석). git
	저장소는 이름 옆에 브랜치가 붙고, 미리보기에 최근 커밋과 내용이 뜬다.
	워크트리 경로를 고르면 메인 저장소의 세션으로 가서 그 워크트리의 윈도우를 연다
	(그 이름의 세션이 이미 있거나 목록 파일에 직접 적은 항목이면 적은 대로 세션).

윈도우 = 워크트리 ~
	저장소 세션 안에서 prefix W 로 브랜치를 고르면 그 워크트리의 윈도우로 간다. 윈도우
	탭(#W)에 브랜치 이름이 나열되어 벌어져 있는 작업이 상태바에 보인다. 이것은 tmux
	위에 얹는 관례라 prefix c 의 보통 윈도우, 저장소 아닌 세션, 순정 tmux new 는 그대로다.
	순정 대응: git worktree add -b <브랜치> <경로> main + tmux new-window -n <브랜치> -c <경로>.
	셸에서: tmux-dev worktree [브랜치|경로] [--base ref] [--layout ide|plain]. --help 에 전부.

	팝업 안. 한 목록에 워크트리(●N 은 열린 윈도우 번호), 브랜치, 원격 브랜치가 순서대로.
	tab			all ↔ worktrees(워크트리만) 필터
	Enter			행의 상태가 동작을 정한다: ●N → 그 윈도우. 워크트리만 → 윈도우 만들기.
				브랜치만 → 워크트리 만들고 윈도우. 원격 → 추적 브랜치부터.
				맞는 후보가 없으면 친 글자로 새 브랜치 (로컬 main 에서 분기, 확인 질문)
	alt-enter		후보가 있어도 친 글자를 새 브랜치 이름으로
	ctrl-x			커서 항목 정리. 매 단계 y/N. 워크트리 → 제거(변경 있으면 거절) + 그 윈도우
				닫기 + 브랜치 삭제 질문. 브랜치 행 → 삭제 질문. prunable 행 → prune.
				먼저 main 을 origin 에 맞출지(fetch --prune, ff-only) 묻는다. 머지 판정이 로컬
				main 기준이라 PR 로 머지한 뒤에는 이게 먼저다(로컬 머지면 "이미 최신"). 브랜치는
				지우기 전에 항상 refs/archive/<날짜>/<브랜치> 에 보관한다. main 에 없는 커밋이
				있으면 그 수를 보여 주고 "보관하고 지울까요?". 메인 체크아웃·원격은 안 건드림.
	행 마커: ●N 열린 윈도우, dirty 커밋 안 된 변경, merged main 에 모두 들어 있음(ff·merge
	commit·rebase 머지는 git cherry, squash 머지는 merge-base 위 임시 단일 커밋으로 판정),
	[ahead n, behind m] 업스트림 대비(main 행의 behind 는 fetch 뒤에만 정확). 목록이 먼저
	뜨고 마커는 잠시 뒤 얹힌다(fzf load 이벤트에서 두 번째 읽기). 머지 판정은 커밋 쌍으로
	~/.cache/tmux-dev/merged/ 에 캐시한다(지워도 됨). 미리보기에 변경 목록과 최근 커밋.
	보관 목록: tmux-dev worktree --archived. 복구: git branch <이름> refs/archive/<날짜>/<이름>
	워크트리 위치: ~/.local/share/tmux-dev/worktrees/<저장소>/<브랜치>. 도구가 관장하는 데이터
	자리라 ls 로는 안 보이고 이 팝업이 창이다. 바꾸려면 git config tmux-dev.worktree.root /
	.name / .location sibling / .setup (--help). Claude Code 가 만든 .claude/worktrees/ 의
	워크트리도 git worktree list 에 있으므로 같은 목록에 뜬다.

7. 이 파일 고치기						*jw-edit*

위치: dotfiles 의 home/dot_config/nvim/doc/jw.txt → ~/.config/nvim/doc/jw.txt
형식: :h help-writing. 첫 줄의 *jw.txt* 와 각 절의 *태그* 가 색인 대상이다.
태그 색인(doc/tags)은 저장할 때와 nvim 시작 시(파일이 색인보다 새로우면)
자동으로 다시 만든다 (config/core/autocmds.lua). 수동: :helptags ~/.config/nvim/doc
새 절을 만들면 *jw-이름* 태그를 붙이고 목차에 |jw-이름| 링크를 추가한다.
"지금 익히는 키" 는 붙은 것을 내리고 다음 묶음을 올리는 식으로 돌린다.
