# prefix S 세션 피커: 멘탈 모델과 설계

상태: 구현됨 (2026-11-07). 코드는 `libexec/tmux-dev-project`, 탐색은 `lib/dirs.sh`. 판단을 바꿀 때는 이 문서부터 고친다.
결정한 내용과 그 이유는 끝의 "결정 기록" 절에 있다.

## 한 줄 모델

디렉토리 하나를 고르면 그 디렉토리의 세션으로 간다. 세션이 없으면 만들고, 디렉토리가 없으면 만든다.

- 세션 = 디렉토리. 세션의 정체는 이름이 아니라 디렉토리의 실제 경로다.
- 모드는 "무엇을 후보로 보여 주나" 만 정한다. 저장소 모드와 디렉토리 모드 어느 쪽에서 골라도 결과는 같다.
- 결과는 한 가지다. 그 경로를 cwd 로 세션을 만들고, 레이아웃대로 첫 윈도우를 채우고, 그 세션으로 전환한다.
  같은 경로의 세션이 이미 있으면 만들지 않고 전환만 한다.

## 원칙

- **피커는 결정만 한다.** fzf 와 그 콜백은 아무것도 만들지 않는다. "무엇을, 어떤 레이아웃으로, 만들지 여부" 를 정해
  상태 파일에 남기고 끝난다. 디렉토리·저장소·세션 생성은 fzf 가 끝난 뒤 스크립트가 한다.
  셸에서 `tmux-dev project <경로>` 로 부르는 것과 같은 길을 탄다.
- **fzf 정석 기능만 쓴다.** 화면은 fzf 의 구획(테두리 라벨, 입력, 목록, 미리보기, 푸터)으로 만들고, 상호작용은
  `transform`, `search`, `execute`, `change-*` 액션으로 한다. fzf 를 고치거나 흉내 내지 않는다.
- **순정 키를 지킨다.** fzf 기본 키에 이미 묶인 키는 쓰지 않는다. 기본 키 목록은 `fzf --man` 의 AVAILABLE ACTIONS 표.
- **Esc 는 닫지 않는다.** 한 단계 뒤로 가거나 검색어를 지운다. 닫기는 ctrl-c. nvim 피커와 같은 규칙이다.
- **질문은 목록을 유지한 채 푸터에서 한다.** fzf 밖의 `read` 프롬프트로 떨어지지 않는다.

## 모드와 후보

| 모드 | 후보 | 탐색 |
|---|---|---|
| 저장소 | `.git` 이 **디렉토리**인 곳 = 메인 체크아웃 | `fd --type d --hidden --no-ignore --prune --glob .git` + 숨김 제외 |
| 디렉토리 | 모든 디렉토리 | `fd --type d` (숨김 제외, .gitignore 존중) |

- `.git` 이 파일인 워크트리와 서브모듈은 `--type d` 만으로 빠진다.
- 탐색 범위는 미리 정하지 않는다. 시작점은 `$HOME` 하나이고 깊이 제한이 없다.
- 공통 제외: 숨김 디렉토리(저장소 모드의 `.git` 자신은 예외)와 ignore 파일의 패턴.
- ignore 파일(`~/.config/tmux-dev/ignore`)은 gitignore 문법이고 `fd --ignore-file` 로 넘긴다. `/` 로 시작하는 패턴은
  홈 기준이다(`fd --base-directory "$HOME"` 으로 돌리기 때문). 파일이 없으면 `Library`, `node_modules` 를 뺀다.
  chezmoi 가 처음 한 번 `/Library`, `node_modules` 로 만들어 준다(`create_ignore`).
- 디렉토리 탐색은 각 저장소의 .gitignore 도 따른다. 저장소 탐색은 `--no-ignore` 라 무시된 곳의 저장소도 찾는다.
  `--no-ignore` 여도 `--ignore-file` 은 적용된다(2026-11-07 확인).
- prefix W 의 dir 모드도 같은 탐색(`list_dirs`)을 쓴다. 그래서 W 의 dir 모드도 홈 전체가 후보다.
- 목록은 fd 가 찾는 대로 흘려 넣는다. 첫 결과는 바로 뜨고 나머지는 뒤따른다.

숨김 디렉토리를 건너뛰는 근거 (2026-11-07, 이 머신 실측):

| 탐색 | 결과 수 | 시간 |
|---|---|---|
| 저장소, 숨김 디렉토리까지 | 244 | 13.3초 |
| 저장소, 숨김은 `.git` 만 허용 | 203 | 1.4초 |
| 디렉토리, 숨김 제외 | 75,495 | 1.5초 |
| 디렉토리, 숨김 포함 | 982,174 | 13.2초 |

빠지는 저장소 41개는 모두 `~/.local`, `~/.claude`, `~/.vim` 같은 도구 데이터 아래다(nvim 플러그인, mise 등).
이런 곳을 열고 싶으면 경로를 직접 친다. 경로 입력은 숨김 디렉토리도 받는다.
성능이 문제 되면 그때 목록 캐시(지난 목록을 먼저 띄우고 뒤에서 갱신)나 범위 제한을 넣는다.

## 목록 순서와 최근 내역

행 순서: 열린 세션 → 최근 연 곳 → 나머지 탐색 결과. 한 경로는 한 번만 나온다.

```sh
{ 열린_세션; 최근; fd ...; } | awk -F'\t' '!seen[$경로]++'   # 앞에 나온 것이 이긴다. 흘려 넣기는 유지된다
```

최근 내역은 파일 하나 `$XDG_STATE_HOME/tmux-dev/history` 에 둔다.

- 한 줄에 `<epoch>\t<실제 경로>`. 최신이 맨 아래. 같은 경로는 최신 한 줄만 남기고 500줄에서 자른다.
- 모드 정보는 저장하지 않는다. 보여 줄 때 판정한다. 저장소 모드는 `.git` 이 디렉토리인 것만, 디렉토리 모드는 전부.
- 지금 없는 경로는 보여 줄 때 건너뛴다. 파일에서 지우지는 않는다(외장 디스크처럼 돌아올 수 있다).
- 언제 기록하나: 이 피커로 세션에 들어갈 때마다. 만들었든 전환만 했든 같다. 셸의 `tmux-dev project <경로>` 나
  `prefix s`, 상태바 클릭으로 옮긴 것은 기록하지 않는다.
- epoch 는 지금 쓰지 않는다. 나중에 빈도·최근도를 섞은 순서(frecency)를 쓸 때 필요해서 남긴다.
- 지금 파일은 한 줄에 경로만 있다. 탭이 없는 줄은 `0\t<경로>` 로 읽고, 다음에 쓸 때 새 형식으로 바뀐다.

검색어를 치면 fzf 는 점수로 다시 정렬한다. 점수가 같으면 `--tiebreak=pathname,index` 로 파일 이름 일치 → 입력 순서를
따른다. 그래서 동점이면 열린 세션과 최근 항목이 앞선다. `--scheme=path` 의 기본 tiebreak 인 `pathname,length` 에서
length(짧은 경로 우선) 자리에 index 를 넣은 것이다. 점수 자체를 바꾸는 우회는 하지 않는다.

## 세션 식별

경로의 정체는 `cd <경로> && pwd -P` 의 결과(심볼릭 링크를 푼 실제 경로)로 한 번 정한다. 세션을 찾는 순서:

1. 세션 옵션 `@tmux-dev-path` 가 그 경로인 세션. 이 피커가 세션을 만들 때 붙인다.
   윈도우의 `@worktree` 와 같은 관례다. 세션 이름을 바꿔도 따라간다(2026-11-07 확인).
2. 옵션이 없는 세션 중 `#{session_path}` 가 그 경로인 것. `tmux new -c` 처럼 순정으로 만든 세션을 존중한다.
3. 없으면 새로 만든다.

같은 경로의 세션이 여럿이면 가장 최근에 붙었던 것(`#{session_last_attached}`)으로 간다.
지금 이 머신에도 `dotfiles` 와 `jw-skills` 두 세션이 같은 경로에 있다.

세션 이름은 표시용이다. 기본은 디렉토리 basename(`.` `:` 은 `_`). 그 이름을 **다른 경로**의 세션이 이미 쓰고
있으면 부모 이름을 붙인다(`app` → `work_app`). 그래도 겹치면 `-2`, `-3` 을 붙인다.

## 찾기와 만들기

찾기는 퍼지로, 만들기는 따로 들어간다. 검색과 생성을 한 입력창에서 다루는 앱들(Obsidian 빠른 전환, VS Code 브랜치 전환,
GitHub 라벨, Notion 멘션)이 쓰는 방식이다. 그 앱들은 만들기를 눈에 보이는 진입으로 두고, 검색어는 **이름**으로만 쓰며,
**위치**는 기본값이나 다음 단계에서 정한다. 처음 구현은 "걸리는 항목이 없을 때 enter = 생성" 이었는데, 그러면 찾을 때는
퍼지 조각을, 만들 때는 전체 경로를 쳐야 해서 두 입력 문법이 섞였다. 그래서 바꿨다.

- **enter 는 열기만 한다.** 커서 항목을 연다. 걸리는 항목이 없으면 아무것도 열지 않고 벨과 함께 푸터에
  "맞는 항목이 없다 · alt-enter 'xxx' 새로 만들기" 를 띄운다. 생성이 아니라는 것을 알려 주는 안내다.
- **alt-enter 는 친 이름으로 새로 만든다.** 검색어가 있으면 푸터에 늘 "alt-enter 'xxx' 새 저장소 만들기" 가 보인다.
  결과가 있어도 친 이름으로 만든다(Obsidian 의 Shift+Enter). 그래서 `dotfiles` 가 걸려도 `dot` 을 만들 수 있다.
  누르면 **위치 피커**가 겹쳐 뜬다.
- **위치 피커**는 디렉토리 목록의 퍼지 선택이다. 위쪽에 최근에 무언가를 만든 부모(◷, `~/.local/state/tmux-dev/parents`),
  그다음 alt-enter 를 누를 때 커서에 있던 항목의 부모(↳), 나머지는 디렉토리 탐색 전부다. 미리보기에 만들어질 경로와
  판정(새로 만든다 / 이미 있다 / git init / 다른 저장소 안)을 보여 준다.
  - enter: 여기에 만들고 연다. 위치를 고르는 enter 가 곧 확인이다(alt-enter 와 위치로 이미 두 번 명시했다).
    같은 이름이 이미 있으면 만들지 않고 연다. 중간에 파일이 있는 등 만들 수 없으면 푸터에 이유를 띄운다.
  - alt-l: 레이아웃 목록이 한 겹 더 뜬다. 고르면 그 레이아웃으로 만들고 연다. esc 면 위치 피커로 돌아온다.
  - esc: 메인 목록으로 돌아온다. 검색어와 커서는 그대로다.
- 이름에 `/` 를 넣으면 중간 디렉토리도 만든다(`apps/web`). `..`, `.`, 빈 칸(`//`), `/`·`~` 로 시작하는 이름은 받지 않는다.
- 저장소 모드의 생성은 `mkdir -p` 뒤 `git init` 이다. 디렉토리 모드는 `mkdir -p` 만.

## 경로 입력

`/` 나 `~/` 로 시작하는(또는 `~` 하나인) 검색어는 경로로 다룬다. 목록에 없는 곳(숨김 디렉토리 아래, 홈 밖, ignore 파일에
걸린 곳)을 여는 길이고, 위치 피커 없이 그 자리에 바로 만드는 길이다.

- **경로 접두 일치로 거른다.** `change` 콜백이 `search:^~/dev/jwlee` 액션을 내보내, 검색어 글자는 그대로 두고 실제 검색만
  바꾼다. `/Users/<나>/...` 로 쳐도 `~/...` 로 맞춘다. 끝 슬래시는 "이 디렉토리 아래" 다.
- **enter**: 걸리는 항목이 있으면 커서 항목. 없으면 그 경로가 있는 디렉토리일 때 연다(목록 밖이어도 묻지 않는다).
  없는 경로면 열지 않고 푸터에 "없는 경로 · alt-enter 만들기: ~/x (git init)" 를 띄운다.
- **alt-enter**: 그 경로에 바로 만든다. 이미 있으면 연다.
- **ctrl-]** 는 커서 항목의 경로를 끝 슬래시 없이 검색어에 채운다. 그 항목 자신이 걸리고 `pathname` tiebreak 덕에
  하위 디렉토리보다 위에 오므로, 채운 직후 enter 는 그 항목을 연다. 이어서 `/이름` 을 치고 alt-enter 면 그 아래에 만든다.
- **검색 대상은 경로 칸 하나다.** 행은 `<~경로>\t<표시>\t<실제 경로>` 이고 `--nth=1` 로 첫 칸만 검색한다. 표시(●, ◷, 브랜치)는
  경로 **뒤**에 붙인다. 앞에 붙이면 `^~/...` 접두 일치가 깨진다.
- 상대 경로는 받지 않는다. 피커를 띄운 패널의 디렉토리에 따라 결과가 달라지는 것이 이전 혼란의 원인이었다.
- 치는 동안 enter·alt-enter 가 할 일을 푸터에 미리 보여 준다. `result` 이벤트에 `bg-transform` 을 묶되 경로 모양 검색어일 때만
  `rebind(result)` 로 켠다(목록이 흘러 들어오는 동안 이벤트가 많이 나서). 검색어가 바뀌면 `bg-cancel` 로 이전 검색어의 판정을 버린다.
  빠르게 치면 낡은 결과가 늦게 도착해 최신 판정을 덮었다(시험에서 확인).

퍼지 대신 접두 일치가 필요한 근거 (홈 아래 디렉토리 75,495개 대상, 모두 존재하지 않는 경로):

| 검색어 | 퍼지 일치 | 접두 일치 | 퍼지 1등 |
|---|---|---|---|
| `~/dev/jwlee/api` | 21 | 0 | `~/dev/jwlee/job-projects/toss-coffee-order/src/apis` |
| `~/dev/jwlee/notes` | 18 | 0 | `~/dev/jwlee/jwenv/dotfiles` |
| `~/dev/test` | 31,393 | 0 | `~/dev/opensources/yup/test` |
| `~/work/demo` | 4,670 | 0 | `~/dev/workspaces/labs/ag-grid-app/src/pages/grid-demo` |

퍼지였다면 Enter 가 엉뚱한 디렉토리를 열었다.

### 친 경로의 판정

경로는 `~` 를 풀고, 끝의 `/` 를 떼고, `.` `..` 을 정리한 뒤 판정한다(`classify`). 위치 피커의 "부모/이름" 도 같은 판정을 쓴다.

| 상태 | enter | alt-enter |
|---|---|---|
| 있는 디렉토리 | 연다. 저장소 모드에서 저장소가 아니면 "git init 은 하지 않는다" 를 푸터에 | 연다 |
| 있는 워크트리(`.git` 파일) | 그 워크트리로 이동 | 같다 |
| 없음 | 열지 않고 안내 | 만든다. 중간 디렉토리도. 저장소 모드는 git init, 다른 저장소 안이면 푸터에 표시 |
| 파일, 중간 경로가 파일, 쓸 수 없음 | 막는다(푸터에 이유) | 같다 |

## 선택 흐름

```
목록 ─enter──────→ 커서 항목 열기 (없으면 벨 + 안내. 경로를 쳤고 있으면 연다)
  ├─alt-l─────→ [레이아웃] ─enter→ 그 레이아웃으로 열기
  │                └─esc→ 목록
  └─alt-enter─→ [위치] ─enter→ 만들고 열기 (이미 있으면 열기)
                  ├─alt-l→ [레이아웃] ─enter→ 그 레이아웃으로 만들고 열기
                  │            └─esc→ [위치]
                  └─esc→ 목록
     (경로를 쳤으면 alt-enter 는 [위치] 없이 그 자리에 만든다)
```

- 겹쳐 뜬 목록(위치, 레이아웃)의 esc 는 한 단계 뒤다. 메인 목록의 esc 는 검색어 지우기다. 닫기는 메인 목록의 ctrl-c.
- 돌아왔을 때 검색어, 커서 위치, 모드, 미리보기 상태가 그대로다. 겹쳐 뜬 목록은 `execute` 로 띄운 별도 fzf 라
  끝나면 원래 fzf 가 그대로 다시 그려진다.
- "끝" 은 결정을 상태 파일에 쓰고 fzf 를 끝내는 것이다. 실제 생성·전환은 그 뒤 스크립트가 한다.

겹쳐 뜬 목록의 esc 는 fzf 기본(abort, 종료 코드 130) 그대로다. 그 fzf 만 끝나고 상태 파일에 고른 값이 남지 않으므로
원래 fzf 는 그것을 "취소" 로 읽는다. ctrl-c 도 같은 결과다. 대안은 같은 fzf 의 목록을 바꿔 끼우는(`reload`) 방식인데,
돌아올 때 1.4초짜리 탐색을 다시 돌리지 않으려면 목록 캐시가 필요하고 커서 복원(`pos`, `--id-nth --track`)도 직접 해야 해서 택하지 않는다.

레이아웃 목록은 `lib/layout.sh` 의 `choose_layout` 을 prefix W 와 같이 쓴다. S 는 `LAYOUT_ESC=abort` 와 `LAYOUT_FZF_OPTS`
(같은 테두리)를 넘긴다. 미리보기 alt-p 순환은 `choose_layout` 안에 있어 W 의 레이아웃 목록도 같다. "이 저장소의 기본으로 저장" 은 레이아웃 목록 안의 alt-enter 이고, 대상이 저장소이거나 새로 만들 저장소일 때만 켠다.

### 워크트리를 고르면

워크트리(`.git` 이 파일) 경로를 고르면 그 워크트리로 이동한다. 세션 = 저장소, 윈도우 = 워크트리 관례를 따른다.

1. 그 워크트리 경로의 세션이 있으면 그리로. 순정 `tmux new -c <워크트리>` 로 만든 세션을 존중한다.
2. 어느 세션에든 그 워크트리를 연 윈도우(`@worktree`)가 있으면 그 윈도우로.
3. 없으면 메인 저장소의 세션(없으면 만든다)에 `tmux-dev worktree -t <세션> <경로>` 로 윈도우를 열고 그리로. alt-l 로 고른
   레이아웃은 이 워크트리 윈도우에 쓴다.

이 읽기는 `open_worktree` 함수 하나에 모았다. "워크트리마다 세션" 으로 바꾸려면 이 함수만 고친다.

## 화면

```
╭─ open session ────────────────────────────────────────────────╮  ← 바깥 테두리 라벨 = 화면 제목
│     repository  directory       │ ~/dev/jwlee/dotfiles  main  │  ← 헤더(--header-first) = 모드 탭. 현재 모드 굵게, 클릭으로 전환
│ ╭──────────────────────────────╮│                             │
│ │ > ~/dev/jw                   ││                             │  ← 입력 상자 | 미리보기
│ ╰──────────────────────────────╯│ a1b2c3 feat: ...            │
│ ╭──────────────────────────────╮│ ...                         │
│ │ ~/dev/jwlee/dotfiles  ● dotfiles main                       │  ← 목록: 경로 뒤에 ● 세션 이름, ◷ 최근, 브랜치
│ │ ~/dev/jwlee/resume  ◷ main   ││                             │
│ ╰──────────────────────────────╯│                             │
│ ────────────────────────────────│                             │
│ enter open · alt-enter new · ·│                             │  ← 푸터: 키 안내 · 만들기 안내 · 경로 판정
╰──────────────────────────────────────────────────────────────╯
```

- **모드 탭은 맨 위 헤더다**(`--header --header-first`, 2026-11-08). tab 이나 모드 이름 클릭(`click-header`)이 `change-header` 로
  바꾼다. 처음에는 바깥 테두리 라벨에 두었는데(미리보기가 켜져 있어도 전체 폭), 옮긴 이유:
  - fzf 는 라벨을 상자의 이름으로 다룬다. 라벨을 클릭해도 이벤트가 전혀 없다(`left-click` 도 안 불린다, 0.74.5 시험).
    헤더는 목록을 다루는 안내·컨트롤 자리이고 `click-header` 가 클릭한 단어를 넘긴다. fzf 문서(ADVANCED.md)의 모드 전환
    예제도 모두 모드 안내를 `--header` 에 둔다.
  - 모드가 바꾸는 것은 목록뿐이다(미리보기는 커서 항목을 보여 줄 뿐). 헤더는 목록 구획에 있어 탭의 폭이 그 범위와 맞는다.
  - 라벨은 겹쳐 뜨는 목록들처럼 화면 제목이 된다(" layout · <경로> ", " new … : where? "). 라벨 = 이 화면이 무엇인가,
    헤더 = 이 목록을 어떻게 보나.
  - 대가는 한 줄. `--header-first` 로 입력 상자 위에 둔다: 탭 → 그 안에서 검색 → 목록 순서이고, 입력과 목록을 가르지 않는다.
  - 탭 이름 사이는 탭 문자다. fzf 는 클릭 단어를 `--delimiter` 로 자르는데 행 칸 구분 때문에 `--delimiter '\t'` 라서,
    공백으로 띄우면 두 탭 이름이 한 단어로 왔다. `--tabstop 2` 라 화면에는 두 칸 간격이다.
  - **클릭이 가끔 안 먹는 이유 (fzf 0.74.5, master 도 같다. 2026-11-08 소스로 확인)**
    - `click-header` 는 버튼을 **뗄 때**, 누른 칸과 **정확히 같은 칸**에서 뗐을 때만 나온다
      (`clicked := wasDown && !me.Down && (mx == pmx && my == pmy)`). 누르는 사이 한 칸만 움직여도(트랙패드) 버려진다.
      목록 항목 클릭은 누를 때 처리해서 이 문제가 없다.
    - 클릭 칸 → 단어 변환(`addClickHeaderWord`)이 글자 수(`token.prefixLength`, rune)를 바이트 위치로 써서 문자열을 자른다.
      앞에 한글 같은 여러 바이트 글자가 있으면 다음 단어의 클릭 범위가 왼쪽으로 밀린다. 탭이 "저장소⇥디렉토리" 였을 때
      "디렉토리" 의 범위가 실제 9~16칸이 아니라 4~11칸으로 잡혀, "디렉" 은 먹고 "토리" 는 안 먹었다.
    - 그래서 피커 화면 문구는 영어로 쓴다(결정 15). 탭 이름은 누를 자리가 넓도록 줄이지 않는다(repository, directory).
- 푸터는 평소에 짧은 키 안내 한 줄이다. 검색어가 있으면 "alt-enter create repository 'xxx'" 가, 경로를 치면 enter·alt-enter 의 판정이, 할 일이 없으면 이유가 그 자리를 차지한다.
  미리보기가 오른쪽에 있으면 푸터는 목록 폭이다(fzf 배치 규칙. 바꿀 수 없다).
- 피커 창(modal floating pane)은 테두리 없이(`new-pane -B none`) 띄운다. **테두리는 fzf 가 그린다.** 모드 탭(헤더),
  화면 제목과 겹쳐 뜨는 목록의 제목(라벨), 입력·목록 구획, 푸터가 모두 fzf 액션 안에서 한 번에 바뀌고, tmux 밖 셸에서도 같은 화면이
  나오기 때문이다. 한 화면은 한 주인이 그린다.
  - pane 테두리(`pane-border-status` + `pane-border-format`)로 바깥만 넘기는 안은 택하지 않았다(2026-11-08). tmux 가 맡을 수
    있는 건 바깥 테두리와 그 한 줄뿐이라 입력·목록 테두리를 위한 모양 번역은 그대로 남고, 탭 갱신은 `tmux set -p`
    호출로 갈라져 fzf 와 다시 그리는 때가 어긋날 수 있으며, 겹쳐 뜬 목록에서 돌아올 때 제목을 되돌려야 한다.
    tmux 3.8 의 pane 테두리에는 rounded 도 없다(3.9 에 들어간다). 처음에 fzf 가 그린 이유는 "팝업 제목은 띄운 뒤 바꿀 수
    없다" 였는데, 패널은 바꿀 수 있어도 위 이유로 결론은 같다.
  - 모양은 tmux 의 떠 있는 창 테두리와 똑같이 맞춘다 (2026-11-07 팝업으로 확인: 모서리·선 글자, 테두리 색, 배경, 제목 위치).
  - 선 모양: tmux `@float-border-lines` → fzf `--border`. rounded→rounded, single→sharp, double→double, heavy→bold.
  - 색: tmux `@float-border-style` 의 fg → fzf `--color border:<색>,label:<색>`.
  - 배경: 런처가 `@float-style` 을 `new-pane -s` 로 넘기고, fzf 의 기본 배경이 그것을 물려받는다.
  - 제목 위치: tmux 는 `╭─ 제목 ─` 이다. fzf 는 `--border-label-pos 3` 이 같다.
  - 색과 선 모양은 피커가 뜰 때 tmux 옵션에서 읽는다(`float_border`). `@float-*` 가 없으면 `popup-*` 를 읽는다.
    `@float-*` 는 tmux.conf 가 팝업과 floating pane 공용으로 두는 사용자 옵션이다(floating pane 에는 전역 스타일 옵션이
    없고, `popup-*` 는 tmux 3.9 에서 없어진다). fzf 가 모르는 색 이름을 넘기면 fzf 가 뜨지 않으므로 `#rrggbb`, `colourN`,
    숫자, 기본 8색 이름만 넘긴다.
- fzf 에 도움말 팝업 기능은 없다. alt-h 를 누르면 미리보기 창을 키 안내로 바꿔 보여 주고(`change-preview`+`show-preview`),
  다시 누르면 원래 미리보기로 돌아간다.
- 목록 행은 `--with-nth 1,2 --nth 1` 이다. `--with-nth '{1}  {2}'` 같은 템플릿을 쓰면 `--nth` 가 합친 문자열 전체에 걸려
  브랜치 이름까지 검색됐다(시험에서 확인). 칸 사이 정렬은 `--tabstop 2` 로 맞춘다.

## 띄우기

prefix S 는 피커를 **modal floating pane** 으로 띄운다(2026-11-08, 그전엔 `display-popup`). tmux 메인테이너가 팝업을
deprecated 로 밝혔고(tmux#5135: "Popups are … going away"), 3.9 부터 `display-popup` 은 floating pane 을 여는 문서 없는
호환 명령으로만 남는다. `popup-*` 옵션은 없어진다. floating pane 과 modal pane(`new-pane -O`)은 3.8 에 이미 있다.

```
prefix S → run-shell -b "tmux-dev open project '#{client_name}' '#{pane_id}' #{q:pane_current_path}"
         → libexec/tmux-dev-open: 크기·가운데 자리·스타일을 계산해
           new-pane -O -K -B none -t <패널> -c <디렉토리> -x/-y/-X/-Y -s <@float-style> -e TMUX_DEV_CLIENT=… tmux-dev project
         → 피커(fzf)는 결정만 → fzf 가 끝나면 만들기·전환 → 스크립트가 끝나면 패널도 닫힌다
```

- **왜 런처를 거치나.** 키를 누른 클라이언트를 알 길이 `run-shell` 의 `#{client_name}` 뿐이다(3.8 에서 시험). `new-pane` 은
  `-e` 값과 명령 문자열의 `#{}` 를 펼치지 않고, 뒤에 이어 붙인 `set -pF @client …` 는 피커가 읽을 때 아직 비어 있었다.
  피커는 패널이라 `-c` 없는 `switch-client` 는 "가장 최근에 쓴 클라이언트" 를 옮긴다. 보통은 키를 누른 클라이언트가
  그것이지만 우연에 기대지 않고 `switch-client -c "$TMUX_DEV_CLIENT"` 로 정한다(`die` 의 상태줄 메시지도 같다).
- **가운데 자리.** floating pane 의 기본 위치는 왼쪽 위 계단식(4,2)이고 `-X/-Y` 는 정수 % 만 받는다(`7.5%` 는 거부).
  런처가 크기와 자리를 칸으로 계산해 넘긴다(% 로 넘기면 크기와 위치가 따로 버림돼 한 칸씩 어긋났다).
- **플래그.** `-O` modal(포커스를 붙잡는다. 창마다 하나), `-K` prefix 까지 피커로(팝업과 같다. 피커 안에서 prefix S 를
  다시 눌러도 겹치지 않는다), `-B none`(테두리는 fzf, 화면 절). `-D` 는 쓰지 않는다: Esc 로 패널이 닫혀 "Esc 는 검색어
  지우기" 와 부딪힌다. zoom 상태에서도 modal 은 위에 뜬다.
- **팝업과 달라진 것.** 피커가 클라이언트가 아니라 창에 속한다. 같은 창을 보는 다른 클라이언트에도 보이고, 전환하는
  순간 원래 창에 잠깐 남았다가 스크립트가 끝나면 닫힌다. 피커가 자기 창이나 세션을 부수는 동작은 없어서(결정만 하고
  만들기·전환은 fzf 뒤) 창에 속해도 문제가 없다. 자기 창을 닫는 동작이 있는 prefix W 는 UX 를 다시 짠 뒤 옮긴다.
- 크기 옵션 이름은 `@tmux-dev-popup-size` 그대로다(W 와 같이 쓴다). S 는 키를 누를 때 읽어서 `prefix :` 로 바꾼 값이 바로 먹는다.

## 키

fzf 기본 키(0.74)와 겹치지 않는 것만 쓴다.

| 키 | 동작 | 비고 |
|---|---|---|
| enter | 열기 | fzf 기본(accept)을 같은 뜻으로 덮는다(판정을 거치게) |
| alt-enter | 친 이름으로 새로 만들기 → 위치 피커 | 비어 있음 |
| esc | 메인 목록: 검색어 지우기 / 겹쳐 뜬 목록: 돌아가기 | 메인은 덮고, 겹쳐 뜬 목록은 기본(abort) 그대로 |
| ctrl-c | 닫기 | fzf 기본 그대로 |
| tab, shift-tab | 모드 전환 | 기본은 multi 선택 토글. multi 를 안 쓰므로 지금도 덮고 있다 |
| ctrl-] | 커서 경로를 검색어에 채우기 | 비어 있음. tmux prefix(C-b, C-a)와도 겹치지 않는다 |
| alt-l (위치 피커) | 레이아웃을 골라 만들기 | 위치 피커 안에서만 |
| double-click | enter 와 같다 | 기본은 accept. 판정을 거치게 덮는다 |
| 모드 이름 클릭 | 그 모드로 | `click-header` 이벤트. 헤더 클릭에 기본 동작은 없다 |
| alt-l | 레이아웃 골라 열기 | 비어 있음 |
| alt-p | 미리보기 오른쪽 → 아래 → 숨김 | 비어 있음 |
| alt-h | 키 안내 열고 닫기 | 비어 있음 |

fzf 0.74 기본 키: ctrl-a b c d e f g h j k l n p q u w y, ctrl-/, alt-b d f, alt-/ bs,
화살표·home·end·pgup·pgdn·del, shift-화살표, enter, esc, tab, shift-tab.
비어 있는 후보: ctrl-o, ctrl-t, ctrl-x, ctrl-r, ctrl-s, ctrl-v, ctrl-], ctrl-space, alt-c, alt-e, alt-h, alt-l, alt-o, alt-p.
(ctrl-s 는 터미널 흐름 제어에, ctrl-r 은 셸 히스토리 습관에 걸릴 수 있다.)

## 구현 구조

- **상태 디렉토리.** 피커를 띄울 때 `mktemp -d` 로 하나 만들고 `trap` 으로 지운다. 경로는 환경변수로 넘겨
  fzf 가 띄우는 모든 콜백이 물려받는다(겹쳐 뜬 fzf 의 콜백까지). 모드, 만들 이름, 고른 위치·레이아웃, 최종 결정을
  파일로 둔다. 프롬프트·라벨 문자열을 파싱해 상태를 되살리지 않는다. 디스크 부담은 1000번에 30MB 이하로 배경 잡음보다 작았다.
- **콜백은 액션 한 줄을 출력한다.** `transform` 의 출력이 여러 줄이면 첫 줄만 적용된다(시제품에서 확인).
  액션은 `+` 로 잇는다. `search:` 꼴은 줄의 맨 끝에만 쓴다. 경로처럼 사용자 글자가 들어가는 인자는 `act` 가
  그 글자에 없는 구분 기호 쌍(`()` `[]` `{}` ...)을 골라 감싼다(man fzf: ACTION ARGUMENT).
- **콜백은 `--on <이벤트>` 로 같은 스크립트를 다시 부른다.** 메인: enter, create, layout, after-layout, after-location, esc,
  change, result, mode, fill, help. 위치 피커: loc-enter, loc-layout, loc-after-layout.
  겹쳐 뜬 단계는 `execute(--choose-location)+transform(--on after-location)` 처럼 이어 붙인다.
- **결정 파일은 칸 구분자로 US(0x1f) 를 쓴다.** 레이아웃 같은 빈 칸이 있는데, 탭이면 bash `read` 가 연속 탭을 하나로 합쳐
  뒤 칸이 앞으로 밀렸다(시험에서 확인. W 에서도 겪은 함정).
- **끝맺음.** 결정 파일이 있으면 fzf 종료 코드와 상관없이 그것을 따른다. 후보 없이 accept 하면 fzf 는 1을 돌려주기 때문이다.
- **fzf 뒤의 행동.** 결정 = (경로, 만들기 여부: 없음/디렉토리/저장소, 레이아웃). 만들기 → 세션 찾기 → 없으면 만들고
  `@tmux-dev-path` 를 붙이고 레이아웃 → 최근 내역 기록 → 전환. 실패는 지금처럼 `tmux display-message` 로도 알린다.
- 셸의 `tmux-dev project <경로>` 는 같은 "fzf 뒤의 행동" 을 바로 탄다. 있는 디렉토리만 받고 최근 내역에는 남기지 않는다.
- **시험.** 격리된 tmux 서버(`tmux -L <이름>`)의 패널에서 피커를 돌리고 `capture-pane` 으로 화면을 확인했다. 세션 전환까지
  보려면 가상 터미널 클라이언트를 붙인다(`script`). 이때 클라이언트의 입력을 `/dev/null` 로 주면 ctrl-d 가 패널로 가서
  fzf 가 바로 끝난다. 끝나지 않는 파이프를 준다. chezmoi 원본(`executable_` 이름)이 아니라 설치된 모양의 사본으로 돌린다.

## 결정 기록 (2026-11-07)

1. **경로 채우기 키는 ctrl-].** fzf·tmux 어디에도 묶여 있지 않다. ctrl-f 는 fzf 기본 forward-char 라 쓰지 않았다.
2. **저장소 모드에서 저장소가 아닌 기존 디렉토리를 친 경우** 그 사실을 알리고 Enter 면 열기만 한다. 이미 있는
   디렉토리에 `git init` 하는 것은 부담이고, 들어가서 하면 된다. 새로 만드는 경우에만 `git init` 한다.
3. **워크트리 경로를 고르면 그 워크트리로 이동한다.** 어느 모드든, 목록에서 골랐든 경로를 쳤든 같다. "이동" 을
   "그 워크트리를 연 윈도우로" 로 읽었다(세션 = 저장소, 윈도우 = 워크트리). 순서는 위 "워크트리를 고르면" 절.
4. **목록 파일 `projects` 는 `ignore` 로 바꾼다.** 범위에서 뺄 것만 적는다. 등록·제거·편집 키는 없앴다.
   머신에 남아 있는 옛 `~/.config/tmux-dev/projects` 는 더 읽지 않는다. 지워도 된다.
5. **목록 순서는 열린 세션 → 최근 고른 곳 → 탐색.** 모드 조건은 세 묶음 모두에 건다. 그래서 워크트리나 저장소 아닌
   경로의 세션은 저장소 모드에 안 보이고 디렉토리 모드에 보인다.
6. **검색어가 있을 때도 최근 항목 우선**은 tiebreak 만 바꿔서 반영했다. 점수가 같을 때만 앞선다.
7. **최근 내역은 피커로 고른 것만** 기록한다.

이어서 정한 것 (같은 날):

8. **만들기는 alt-enter 로 따로 들어간다.** enter 는 열기만 하고, 빈 결과의 enter 는 벨과 안내만 낸다. 처음의 "목록에 없지만
   있는 디렉토리, 열까요?" 질문은 생성이 아님을 알리려던 것이었는데, 생성이 분리되면서 필요 없어졌다.
9. **경로 모양 검색어는 남긴다.** 접두 일치로 거르고, enter 는 있으면 열고, alt-enter 는 위치 없이 그 자리에 만든다.
10. **위치 피커 후보는 디렉토리 전부.** 저장소 모드에서도 위치는 아무 디렉토리나 될 수 있다.
11. **레이아웃은 위치 피커에서 alt-l.** 메인의 alt-l 은 있는 항목을 레이아웃 골라 열기다.

2026-11-08:

12. **팝업 대신 modal floating pane.** prefix S 만 먼저 옮긴다. 나머지 팝업(lazygit, nvim, 치트시트)과 prefix W 는 그대로다.
    W 는 S 처럼 UX 를 다시 짠 뒤 옮길지 본다. 방식과 이유는 "띄우기" 절.
13. **테두리는 계속 fzf 가 그린다.** pane 테두리로 바깥만 넘기는 안은 더 간결해지지 않는다(화면 절).
14. **모드 탭은 헤더로, 라벨은 화면 제목으로.** 모드 이름을 클릭해 바꾸고 싶다는 요청에서 시작했다. 라벨에는
    클릭 이벤트가 없고, 따져 보니 헤더가 fzf 의 쓰임새와 모드의 범위(목록)에 더 맞았다. 이유는 화면 절.
15. **피커 화면 문구는 영어로.** "디렉토리" 탭의 뒤쪽 절반을 누르면 안 먹었는데, fzf 의 클릭 단어 계산이 여러 바이트 글자에서
    틀리기 때문이었다(화면 절). 사용자가 UI 언어는 영어로 바꿔도 좋다고 해서 prefix S 의 화면 문구(제목, 탭, 푸터, 판정,
    도움말, 레이아웃 목록, 오류)를 영어로 바꿨다. 주석과 이 문서는 한국어 그대로다. prefix W 의 문구는 W 를 다시 짤 때 바꾼다
    (레이아웃 목록과 공용 오류는 lib 이라 W 에서도 영어로 보인다).

## 남은 것

- 미리보기 창의 대체 배치 기준값 `<60(down,...)` 은 피커 전체 폭이 아니라 **미리보기 창의 폭**을 잰다(fzf 매뉴얼).
  45% 에 기준 60 이면 피커 창 안쪽 폭이 약 134칸 이상이어야 오른쪽에 뜨고, 이 기준값이 있으면 `change-preview-window` 의
  hidden 도 먹지 않는다. S 는 기준값을 빼고 alt-p 순환을 넣었다. **prefix W 는 아직 이 기준값을 쓴다.**
- prefix W 피커도 같은 방향(헤더 탭, 푸터 확인, 상태 디렉토리)으로 정리할 차례다. W 의 ctrl-x 정리는 여러 단계를
  묻는 흐름이라 푸터 확인으로 옮기려면 단계 상태가 더 필요하다.
