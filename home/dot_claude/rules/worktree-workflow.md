# 워크트리 작업 흐름

대화는 어디서 시작해도 되지만, 파일을 고치는 작업은 그 작업의 워크트리에서 한다.

## 작업 하나 = 워크트리 하나

- git 저장소에서 파일을 고치기 시작할 때, 아직 워크트리가 아니면 `EnterWorktree` 로 작업 이름의 워크트리를 만들어 들어간다.
  사용자가 "여기서 해"라고 했거나 저장소가 아니면 예외다.
- 새 워크트리의 베이스가 의도와 맞는지 본다. `EnterWorktree` 는 원격 기본 브랜치에서 가르므로, 로컬 기본 브랜치가
  앞서 있으면(`git log --oneline origin/<기본>..<기본>`) 시작하기 전에 맞춘다.
- 관련 없는 다음 작업은 `ExitWorktree`(keep) 뒤 새 이름으로 `EnterWorktree`. 앞서 쓰던 워크트리로 돌아갈 때는 `path` 로 들어간다.

## 스택: 앞 작업 위에 쌓는 작업

리뷰는 따로 받지만 앞 작업의 코드가 있어야 하는 작업은 stacked PR 로 만든다.

- 기본: 같은 세션·같은 워크트리에서 브랜치만 바꿔 이어 간다 (`gh stack` 이 있으면 `gh stack add <브랜치>`,
  없으면 `git switch -c <브랜치>`).
- 아래 브랜치를 고칠 때는 체크아웃을 바꾸지 않고 fixup 커밋 + `git -c sequence.editor=: rebase -i --autosquash --update-refs --keep-base <스택의 base>`.
- 아래 브랜치로 따로 워크트리를 만들지 않는다. 그 브랜치를 체크아웃할 수 없게 되고 `--update-refs` 도 그 브랜치를 옮기지 않는다.

## 정한 작업을 넘기기

- 원칙: 한 워크트리에서 동시에 파일을 고치는 세션은 하나뿐이다. 새 세션은 언제나 자기 워크트리에서 일한다.
- 대화로 범위가 정리돼 다른 자리나 새 맥락에서 진행하는 게 낫다고 보이면 제안하고, 사용자가 확인한 뒤에 넘긴다.
  수단은 `jw:handoff` 스킬이고, 방식은 넷이다.
  - `move`: 지금 세션을 그 브랜치의 워크트리로 옮긴다. 브랜치 이름·베이스·스택을 정해서 옮길 때.
    (그냥 작업을 시작하며 들어가는 것은 위의 `EnterWorktree` 로 충분하다.)
  - `fork`: 대화를 복사한 세션을 다른 워크트리에 띄우고 이 세션은 남는다. 여러 워크트리로 나눠 넘길 때도.
  - `fresh`: 지시서 한 장으로 시작하는 세션을 다른 워크트리에 띄운다. 대화가 길거나 결론만 넘기면 될 때.
  - `here`: 이미 그 작업의 워크트리에서 길게 설계했으면, 지시서를 쓰고 같은 워크트리에서 대화만 비워 다시 시작한다.
    새 세션을 띄우지 않으므로 위 원칙과 맞는다. 대화를 비우는 것은 사용자가 한다.
- `start_session` 도구가 있으면(Claude 데스크톱 앱) `fork`·`fresh` 는 그것으로 `use_worktree: true`. 나머지는 스킬.
- 도구가 못 하는 방식(Cursor 의 `move`·`fork`)은 스킬이 확인 단계에서 대신 쓸 방식을 소개한다.
- 스택의 다음 단계를 넘길 때:
  - 지금 대화 맥락이 많이 필요하고 대화가 아직 길지 않으면 넘기지 말고 이 세션에서 이어 간다.
  - 원본 대화를 남겨 두고 깨끗한 지시서로 시작하고 싶으면, 지금 브랜치를 커밋한 뒤 그 끝에서 새 브랜치·새 워크트리로 넘긴다
    (`start_session` 의 `source_branch`, 또는 `jw:handoff` 의 `--base <지금 브랜치>`).
  - 그렇게 스택이 워크트리 두 곳에 나뉜 동안 아래 브랜치를 고치면, 위 워크트리에서
    `git rebase --onto <아래 브랜치> <예전 아래 끝>` 으로 따라간다. 아래 세션이 끝나면 그 워크트리를 비워(`git switch --detach`)
    스택을 위 워크트리 한 곳으로 모은다.
  - 같은 워크트리에서 브랜치만 바꿔 새 세션을 띄우지 않는다. 쉬고 있는 원본 세션의 작업 트리가 바뀐다.

## 서브에이전트

- 서로 독립인 조각을 결과만 받으면 될 때는 `Agent` 를 `isolation: "worktree"` 로 띄운다.
- 서브에이전트 워크트리는 기본 브랜치에서 갈라지므로, 스택은 서브에이전트 하나가 처음부터 끝까지 맡거나
  지시에 "`git switch -c <새 브랜치> <앞 브랜치>` 로 시작"을 넣는다.
- 마지막 보고에 브랜치 이름과 PR 링크를 적게 한다.
