# 설계: 피커가 한 일의 결과 알리기 (prefix S, prefix W)

> 상태: 구현 (2026-11-26). 제안(2026-11-25)을 사용자가 "제안대로" 정했다. 아래 "정한 것" 과 "구현" 절.

## 문제

prefix W 에서 서브모듈이 든 워크트리를 `clean up` 했는데 `git worktree remove failed: … containing submodules …` 로
실패했다. 패널은 닫혔고 워크트리·브랜치는 남았다. 메시지는 푸터에 노란 글자로 떴지만 눈에 띄지 않아서, 사용자는 지워진 줄 알았다.

만들기에서도 같은 일이 있었다. 푸터에서 묻던 확인은 놓치기 쉬워서 겹쳐 뜨는 만들기 목록으로 옮겼다(worktree-picker.md 결정 14).
고르는 쪽은 그렇게 해결했지만, **결과를 알리는 쪽은 아직 전부 푸터 한 줄**이다.

푸터는 화면 맨 아래 한 줄이고, 키 안내가 늘 그 자리에 있어서 바뀌어도 눈이 가지 않는다. 결과가 늦게 오면(정리는 백그라운드
작업이다) 사용자는 이미 다른 곳을 보고 있다. 벨은 터미널·tmux 설정에 따라 들리지 않는다.

## 지금 결과가 나가는 곳

| 상황 | 언제 | 어디에 | 문제 |
|---|---|---|---|
| 키 안내, 판정 (enter 가 할 일) | 늘 | 푸터 | 없음. 원래 자리 |
| 할 일이 없음, 막힘 (`nope`: dirty, locked, no match …) | 키를 누른 즉시 | 벨 + 푸터 | 대체로 괜찮다. 막 눌렀으니 화면을 보고 있다 |
| 정리 진행 | 작업 중 | 푸터 스피너 | 없음 |
| **정리 결과 (성공·실패)** | 작업이 끝난 뒤 (몇 초 뒤) | 푸터 (+ 실패면 벨) | **이번 사례.** 실패해도 성공과 같은 자리, 긴 에러는 마지막 줄만 |
| **한꺼번에 정리 일부 실패** | 끝난 뒤 | 푸터 `N failed: <첫 에러만>` | 나머지 실패 이유는 볼 길이 없다 |
| **피커를 닫은 뒤 끝난 정리** | 끝난 뒤 | **없음** | 상태 디렉토리가 지워져 결과가 버려진다 |
| fzf 가 끝난 뒤 실행 실패 (`die`: worktree add 실패 …) | 피커가 닫힌 뒤 | 상태줄 5초 | 놓치기 쉽다 |
| setup 실패 | 실행 화면 | 실행 화면 제목 + 키 하나 기다림 (`frame_hold`) | 없음. 이미 앞에 띄운다 |
| 런처 실패 (`new-pane` 실패) | 피커가 뜨기 전 | 상태줄 5초 | 드물다 |

## 원칙

**알림의 무게는 "결과가 요청과 다른가" 와 "알릴 때 사용자가 화면을 보고 있나" 로 정한다.**

| 단계 | 언제 | 보여 주는 곳 | 닫기 |
|---|---|---|---|
| **안내** | 요청한 대로 됐다 | 푸터 (지금처럼) | 다음 동작에 밀려난다 |
| **거절** | 키를 누른 즉시 할 수 없다고 판정했다 (아무것도 안 했다) | 벨 + 푸터 (지금의 `nope`) | 다음 동작에 밀려난다 |
| **주의** | 시작한 일이 요청과 다르게 끝났다. 실패했거나, 일부만 됐거나, 무언가 남았다 | **결과 시트**: 겹쳐 뜨는 목록 | 사용자가 닫아야 닫힌다 |

- 거절이 푸터로 충분한 이유: 사용자가 방금 키를 눌렀고, 아무것도 바뀌지 않았다. 다시 눌러도 같은 이유가 나온다.
- 주의는 사용자가 확인해야 사라진다. "됐겠지" 하고 넘어가면 안 되는 결과이기 때문이다.
- 성공은 주의로 올리지 않는다. 매번 시트를 닫게 만들면 시트도 푸터처럼 습관적으로 넘기게 된다.
- 고르는 것과 같은 모양을 쓴다(session-picker.md 의 "고르는 것은 겹쳐 뜨는 목록에서"). 새 화면 요소를 만들지 않는다.

## 결과 시트

정리가 끝났을 때 결과에 주의가 하나라도 있으면, 메인 목록 위에 목록을 하나 겹쳐 띄운다. 모양은 정리 목록·만들기 목록과 같다.

```
┌─ clean-up: 1 of 3 not done ─────────────┬──────────────────────────────────────────────┐
│ > ✗ feat-sub   not removed              │ feat-sub: nothing was removed                │
│   ✓ feat-a     cleaned up               │                                              │
│   ✓ feat-b     cleaned up               │ its panes were closed. the worktree and the  │
│                                         │ branch are still there.                      │
│                                         │                                              │
│                                         │ why                                          │
│                                         │   submodule libfoo: 2 unpushed commit(s)     │
│                                         │   would be lost with ~/…/worktrees/app/feat- │
│                                         │                                              │
│                                         │ to do                                        │
│                                         │   push libfoo's commits (enter opens the     │
│                                         │   worktree), then ctrl-x on the row again    │
│                                         │                                              │
├─────────────────────────────────────────┴──────────────────────────────────────────────┤
│ enter open feat-sub · esc back to the list                                              │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

- **제목이 결과를 말한다**: `clean-up: 1 of 3 not done`, `clean-up failed: feat-sub`, `clean-up done with 1 warning`.
- **행은 항목 하나씩**, 문제가 있는 것이 위에 온다: `✗` 실패(아무것도 안 했거나 중간에 멈춤), `!` 됐지만 남은 것이 있음,
  `–` 건너뜀, `✓` 됨. 성공한 것도 함께 보여서 전체 그림이 보이게 한다.
- **미리보기는 그 항목의 전부**를 보여 준다. 무엇이 일어났나(닫힌 패널, 남은 워크트리·브랜치), 왜(에러 전체. 마지막 줄만
  자르지 않는다), 무엇을 하면 되나(명령), 복구 방법(보관 ref).
- **커서는 첫 번째 문제 행**에 둔다. enter 는 그 항목의 워크트리 창을 연다. 문제를 고치러 가는 길이 가장 흔한 다음 동작이고,
  여는 것은 안전하다. 그래서 enter 를 연달아 눌러도 아무것도 지워지지 않는다(정리 목록의 "안전한 행이 맨 위" 와 같은 원칙).
  열 수 없는 항목(브랜치만 있는 행)이면 enter 도 esc 와 같다.
- **esc 는 시트를 닫고 메인 목록으로** 돌아간다(한 단계 뒤로). 목록은 이미 다시 읽혀 있고, 푸터에는 한 줄 요약이 남는다.
- **언제 뜨나**: `cleanup_tick` 이 `finished` 를 봤을 때. 정리 중에는 `busy` 가 다른 키를 막고 있어서 사용자는 대개 기다리는
  중이다. 시트가 스피너 자리를 이어받는 셈이라 갑자기 끼어드는 느낌이 적다.
- **건너뛴 것만으로는 뜨지 않는다.** 한꺼번에 정리에서 dirty 라 미리 빠진 항목은 정리 목록의 미리보기에서 이미 보였다.
  다른 이유로 시트가 뜨면 거기에 `–` 행으로 함께 나온다.

## 피커가 없을 때: 알림함

피커를 닫은 뒤 정리가 끝났거나, fzf 가 끝난 뒤의 실행이 실패하면 시트를 띄울 화면이 없다. 이런 결과는 사라지지 않게 남긴다.

- 작업은 결과를 상태 디렉토리가 아니라 **알림함** `~/.local/state/tmux-dev/notices/` 에 한 파일씩 쓴다(시각·저장소·항목 기록).
  피커가 살아 있으면 피커가 바로 읽고 지운다. 피커가 없으면 파일이 남는다.
- 남았을 때는 **바로 상태줄에** 한 줄을 띄운다: `tmux-dev: clean-up of feat-sub not done · prefix W to see`.
  `display-message -d 0` 으로 띄워 키를 누를 때까지 남긴다.
- **다음에 W 나 S 를 열면 결과 시트부터** 뜬다. 알림함은 저장소를 가리지 않는다(S 에서 열어도 W 의 결과가 보인다). 거기서
  enter 를 누르면 그 항목으로 가고, esc 를 누르면 원래 피커로 간다. 어느 쪽이든 본 알림은 지운다.
- 안내 단계(성공)는 알림함에 넣지 않는다.

## fzf 가 끝난 뒤의 실패: 실행 화면에 붙잡기

결정을 실행하다 실패하면(`git worktree add` 실패, 경로가 이미 있음, 세션을 만들 수 없음 …) 지금은 `die` 가 상태줄에 5초 띄우고
패널이 닫힌다. setup 실패는 이미 실행 화면에서 제목을 `setup failed · <브랜치>` 로 바꾸고 키 하나를 기다린다(`frame_hold`).
**이 방식을 실행 중의 모든 실패로 넓힌다.** 실행 화면이 바로 그 자리에 떠 있으니 거기서 보여 준다.

- 피커 패널(`TMUX_DEV_PICKER_PANE=1`)에서 실행 중일 때만 그렇게 하고, 셸 CLI 와 Claude 훅은 지금처럼 stderr 로 내보낸다.
- 제목은 `failed · <할 일>`, 본문은 에러 전체와 할 일.

## 단계별로 어떻게 바뀌나

| 결과 | 지금 | 제안 |
|---|---|---|
| clean up 성공 (보관 ref 포함) | 푸터 | 푸터 (안내) |
| keep branch 성공 | 푸터 | 푸터 (안내) |
| 정리 실패: dirty (실행 때 다시 본 것), 서브모듈, 프로세스가 안 끝남, git 실패 | 푸터 + 벨 | **시트** (주의) |
| 한꺼번에 정리 일부 실패 | 푸터 `N failed: <첫 에러>` | **시트**, 항목마다 이유 |
| 피커를 닫은 뒤 끝난 정리 (실패) | 사라짐 | **알림함 → 상태줄 + 다음에 열 때 시트** |
| "this window closes when you leave the picker" | 푸터 | 푸터 (예상된 일. 안내) |
| ctrl-x·enter 의 거절 (`nope`) | 벨 + 푸터 | 그대로 (거절) |
| 실행 중 실패 (`die`, 피커 패널) | 상태줄 5초 | **실행 화면에 붙잡기** |
| setup 실패 | 실행 화면에 붙잡기 | 그대로 |
| 런처 실패 | 상태줄 5초 | 상태줄, 키를 누를 때까지 (`-d 0`) |

## 택하지 않은 안

- **푸터를 더 눈에 띄게** (굵게, 반전, 깜빡임, 여러 줄): 그래도 늘 보던 자리의 한 줄이다. 이번 메시지도 이미 노란색이었다.
  여러 줄로 늘리면 목록이 줄었다 늘었다 한다.
- **벨만 키우기**: 터미널·tmux(`bell-action`, `visual-bell`) 설정에 따라 들리지도 보이지도 않는다. 이미 실패에 벨이 울렸다.
- **tmux `display-popup` 이나 `display-message`**: 피커는 fzf 가 그리는 화면이다("고르는 화면은 한 주인이 그린다"). 그 위에
  tmux 팝업을 얹으면 키 입력 주인이 둘이 된다. 상태줄은 피커가 없을 때의 보조로만 쓴다.
- **미리보기에 결과 띄우기**: 미리보기는 커서 행을 따라가므로 커서를 움직이면 사라진다.
- **헤더에 배너**: 헤더는 모드 탭 자리이고, 한 줄을 더하면 목록 높이가 바뀐다. 거기에 놓아도 결국 곁눈으로 보는 자리다.
- **OS 알림** (`osascript`, `notify-send`): 터미널 밖으로 나가고, 원격 접속에서는 닿지 않는다.

## 구현

- 공용(`lib/picker.sh`): 알림함(`notice_new`, `notice_pending`), 결과 시트(`notice_sheet`, `notice_rows`, `notice_preview`),
  시트의 enter(`notice_pick`), 메인 목록이 이어받기(`on_after_notice`), 피커가 끝난 뒤 열기(`notice_open_after`),
  피커가 뜰 때 남은 알림(`notice_start_bind`), 실행 화면에서 실패로 끝날 때 붙잡기(`frame_exit`, EXIT 트랩).
  두 피커가 `--notice-sheet`·`--notice-preview`·`--notice-pick`·`--after-notice` 를 이 함수로 넘긴다.
- 알림 디렉토리: `title`, `items`(항목 한 줄씩: `상태 US 이름 US 요약 US 세션 US 열 경로`), `detail.<N>`(미리보기),
  `ready`(다 썼다는 표시. 쓰는 중인 것은 읽지 않고, 지울 때도 이 표시가 있는 것만 지운다).
  자리는 `$XDG_STATE_HOME/tmux-dev/notices` (`TMUX_DEV_NOTICES`). 정리 작업은 tmux 서버의 환경(`run-shell -b`)에서 돌아
  `XDG_STATE_HOME` 이 피커와 다를 수 있어서, 피커가 작업을 띄울 때 이 자리를 넘긴다.
- 정리(`clean_one`)는 한 일(`ONE_DID`), 실패 종류(`ONE_KIND`: dirty · submodule · processes · unchecked · git),
  git 출력 전체(`ONE_OUT`), 서브모듈별 잃을 것(`SUB_LIST`)을 남긴다. `record_item` 이 이것으로 항목 한 줄과 미리보기
  (`done` · `still there` · `why` · `to do` · `restore`)를 만들고, 실패가 하나라도 있으면 `cleanup_job` 이 알림함에 쓴다
  (`write_notice`). 한꺼번에 정리에서 미리 빠진 것(`bulk_skip`)과 keep 에서 워크트리 없는 브랜치 행은 `skip` 한 행이다.
- `cleanup_tick` 이 `finished` 와 함께 `notice` 를 보면 목록을 다시 읽고 푸터에 한 줄을 남긴 뒤 `execute(--notice-sheet)` 로
  시트를 띄운다. 피커가 그새 끝났으면(작업이 끝날 때 상태 디렉토리가 없다) 작업이 상태줄에 `display-message -d 0` 으로
  알린다(키를 누를 때까지). 알림은 남아 다음에 S·W 를 열 때 `start` 이벤트에서 시트가 먼저 뜬다.
- 시트의 enter 는 그 워크트리가 아직 있으면 상태 `notice_open` 에 남기고 시트와 메인 목록을 끝낸다. 피커가 끝난 뒤
  `notice_open_after` 가 prefix W 의 셸 호출(`tmux-dev worktree -t <세션> <경로>`)로 창을 열고 그 세션으로 옮긴다. S 에서 봐도
  같다("피커는 결정만" 그대로). 없으면 enter 는 닫기와 같다.
- `die` 는 실행 화면(테두리를 켠 뒤)이면 상태줄에 띄우지 않고 끝낸다. EXIT 트랩의 `frame_exit` 가 제목을 `failed · <할 일>`
  로 바꾸고 키 하나를 기다린다. `set -e` 로 끊긴 명령도 같다. 런처 실패는 상태줄에 `-d 0`.
- 시험(`test/tmux-dev/windows`의 "결과 시트" 절): 실패한 정리가 남긴 알림(항목·제목·미리보기), 한꺼번에 정리의 기록,
  성공만 한 정리는 알림이 없음, 시트의 행 순서(실패 먼저)와 다 본 뒤 지우기, enter 의 두 경우.
- 시험하지 못한 것: 실제 fzf 화면(시험은 가짜 fzf 를 쓴다. 이 저장소의 시험 방식), `start` 이벤트의 `execute`,
  실행 화면의 붙잡기(tmux 패널이 필요하다), 피커가 끝난 뒤 작업이 상태줄로 알리는 경우.

## 정한 것 (2026-11-26, 사용자: "제안대로")

1. 시트의 enter: 그 항목의 창 열기.
2. 피커가 없을 때: 상태줄 + 다음에 열 때 시트.
3. 상태줄에 남은 알림 수를 늘 보이기: 나중에.
4. 순서: ① 기록 구조 + 결과 시트(W 정리) → ② 알림함 → ③ 실행 화면에 붙잡기 일반화(S·W). 셋 다 이번에 넣었다.
