# tmux-dev 사용 가이드

tmux-dev 는 tmux 의 세션·윈도우·패널을 개발 작업 단위에 대응시키는 tmux 확장이다. 키 두 개로 프로젝트를 열고
git 워크트리를 만들고 정리한다.

| tmux | 개발 작업 | 여는 키 |
|---|---|---|
| 세션 | 프로젝트 (디렉토리 하나) | `prefix S` |
| 윈도우 | 워크트리 (브랜치 하나) 또는 디렉토리 | `prefix W` |
| 패널 | 역할 (셸, nvim, dev 서버) | 레이아웃이 정한다 |

tmux 의 기능을 대체하지 않고 그 위에 얹는다. `prefix c` 로 만든 보통 윈도우, `tmux new` 로 만든 세션도 그대로 쓸 수 있다.

## 이 가이드의 대상

- 이 dotfiles 를 적용한 머신에서 tmux 를 쓰는 사람
- 여러 저장소와 브랜치를 오가며 작업하고, 브랜치마다 작업 공간을 따로 두고 싶은 사람
- Claude Code 같은 에이전트에게 워크트리 단위로 일을 맡기는 사람

tmux 의 기본 개념(prefix 키, 세션·윈도우·패널)과 git 브랜치를 안다고 가정한다.

- `home/dot_config/tmux/plugins/tmux-dev/session-picker.md` — `prefix S` 설계
- `home/dot_config/tmux/plugins/tmux-dev/worktree-picker.md` — `prefix W` 설계
- `home/dot_config/tmux/plugins/tmux-dev/claude-code.md` — Claude Code 연동 설계

## 한눈에 보기

```
prefix S ─▶ 디렉토리를 고른다 ─▶ 그 디렉토리의 세션으로 전환 (없으면 만든다)
prefix W ─▶ 브랜치나 디렉토리를 고른다 ─▶ 지금 세션에 그 윈도우를 연다 (워크트리가 없으면 만든다)
          └─ ctrl-x ─▶ 끝난 워크트리 정리 (윈도우 닫기 → 워크트리 제거 → 브랜치 보관 후 삭제)
```

새 세션·윈도우는 기본으로 **셸 하나(`plain` 레이아웃)** 로 열린다. 다른 배치(셸 | nvim 등)는
[레이아웃 바꾸기](how-to.md#레이아웃-바꾸기)를 본다.

## 용어

| 용어 | 뜻 |
|---|---|
| 피커 | `prefix S`·`prefix W` 가 띄우는 fzf 목록 창. 화면 가운데에 modal floating pane 으로 뜬다 |
| 모드 | 피커가 후보로 보여 주는 대상의 종류. 피커 맨 위의 탭으로 표시된다 |
| 세션 디렉토리 | 세션이 대표하는 디렉토리. 세션 옵션 `@tmux-dev-path`, 없으면 세션의 시작 경로 |
| 메인 체크아웃 | `.git` 이 디렉토리인 저장소 본체. 워크트리는 `.git` 이 파일이다 |
| 베이스 브랜치 | 새 브랜치가 갈라지고 머지 여부를 판정하는 기준. 보통 로컬 `main` |
| 레이아웃 | 새 윈도우의 어느 패널에 무엇을 띄울지 정한 규칙. tmux 의 `select-layout`(패널 크기 배치)과는 다르다 |
| 보관 ref | 브랜치를 지우기 전에 남기는 사본. `refs/archive/<날짜>/<브랜치>` |
