브랜치 워크트리에서 **새 Claude Code 세션**을 열고 작업 지시서를 첫 메시지로 넣는다. 새 세션은 이 대화를 전혀 보지
못한다. 이 세션(원본)은 메인 체크아웃에 남아 설계를 계속한다. Cursor 등 다른 에이전트에서 불러도 새 세션은 Claude Code
세션이다 (`claude` 가 PATH 에 있어야 한다).

**인자**: 사용자가 입력한 인자 원문은 아래 명령의 heredoc 앞부분에 이미 들어 있다. 원문이 비어 있거나 첫 낱말이 브랜치
이름이 아니라 문장으로 보이면 실행하지 말고 브랜치 이름을 물어본다. 그 밖에는 고치거나 따옴표를 붙이지 말고 그대로 둔다.
스크립트가 원문에서 브랜치·`--in-stack`·`--new-worktree` 를 읽고, 그 뒤의 추가 지시는 지시서 끝에 원문 그대로 붙인다.
아래에서 "브랜치"는 원문의 그 브랜치다.

1. 새 세션에게 줄 작업 지시서를 쓴다. 이 대화를 처음 보는 사람이 그것만 읽고 바로 시작할 수 있어야 한다.
   "위에서 말한", "앞서 정한" 처럼 이 대화를 가리키는 표현은 쓰지 않고 내용을 직접 적는다.
   - 작업 디렉토리는 브랜치의 워크트리이고, 메인 체크아웃의 파일은 수정하지 않는다는 것
     (`--in-stack` 이면: 작업 디렉토리는 스택 워크트리이고 거기 체크아웃된 위 브랜치를 바꾸지 않으며, 그 브랜치의 커밋을
     겨냥한 fixup 커밋 + `git -c sequence.editor=: rebase -i --autosquash --update-refs --keep-base <그 브랜치의 base>` 로
     고친다는 것)
   - 목표와 배경 (왜 하는지)
   - 범위: 할 것과 하지 않기로 한 것
   - 설계 결정과 그 이유, 관련 파일·함수의 경로
   - 완료 조건과 확인 방법 (돌릴 테스트·명령)
   - 남은 질문 (스스로 정하지 말고 사용자에게 물을 것)
   - 첫 번째로 할 일
   - 추가 지시는 스크립트가 붙이므로 다시 옮겨 적지 않는다. 그것을 반영한 계획만 위 항목에 쓴다
2. 인자 원문과 그 지시서를 표준 입력으로 넘겨 Bash 로 한 번 실행한다. `WORKTREE_HANDOFF_PROMPT` 줄 앞은 인자 원문,
   뒤는 1의 지시서다. 지시서에 `WORKTREE_HANDOFF_PROMPT` 나 `WORKTREE_HANDOFF_EOF` 만 있는 줄은 넣지 않는다.
   세션을 띄우는 방식은 스크립트가 정한다 (tmux 안이면 새 윈도우, 아니면 `claude --bg`). 사용자가 방식을 말했을 때만
   `--open bg|tmux|none` 을 붙인다:
   ```
   worktree-handoff fresh --args-file - --prompt-file - <<'WORKTREE_HANDOFF_EOF'
   $ARGUMENTS
   WORKTREE_HANDOFF_PROMPT
   <1의 지시서>
   WORKTREE_HANDOFF_EOF
   ```
   `worktree-handoff` 를 찾지 못하면(command not found) 이 플러그인의 `bin/worktree-handoff` 를 절대 경로로 부른다.
   이 SKILL.md 가 있는 디렉토리에서 두 단계 위(`../../bin/`)다.
3. 실패하면 오류를 그대로 보여 주고 멈춘다. 백그라운드로 띄우지 못했을 때도(`open:` 이 실패, 종료 코드 1) 워크트리와
   `run:` 줄은 출력되니 함께 보여 준다.
   - **스택 워크트리**: 브랜치가 어디에도 체크아웃돼 있지 않은데 그 브랜치를 품은 스택 워크트리가 있으면 스크립트가
     옵션 없이는 멈춘다. 오류를 보여 주고 어느 쪽으로 할지 묻는다. 워크트리 하나에서 브랜치를 바꿔 가며 쌓는 스택이면
     `--in-stack`(그 스택 워크트리를 쓰고 체크아웃은 바꾸지 않는다), 따로 떼어 작업할 거면 `--new-worktree` 다.
     답을 받으면 `fresh` 뒤에 그 옵션을 붙이고, `--in-stack` 이면 지시서에 위의 fixup 방법을 넣어 다시 실행한다.

   성공하면 출력된 워크트리 경로, 세션 이름, `open:` 줄을 알리고 `attach:` · `run:` · `resume:` 줄 가운데 출력된 것을
   명령 그대로 보여 준다. 그 세션에 들어가는 것은 사용자가 한다. 그 뒤로 이 원본 세션에서는 그 워크트리의 파일을
   편집하지 않는다.
