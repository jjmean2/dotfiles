---
name: handoff-fresh
description: 대화를 포크하지 않고, 자기완결적인 작업 지시서를 첫 메시지로 넣은 새 Claude 세션을 브랜치 워크트리의 새 tmux 윈도우에서 연다. 사용자가 /jw:handoff-fresh 로 부를 때만 쓴다.
argument-hint: <브랜치> [추가 지시]
disable-model-invocation: true
allowed-tools: Bash(worktree-handoff:*)
---

브랜치 `$0` 의 워크트리에서 **새 세션**을 열고 작업 지시서를 첫 메시지로 넣는다. 새 세션은 이 대화를 전혀 보지 못한다.
이 세션(원본)은 메인 체크아웃에 남아 설계를 계속한다.

`$0` 이 비어 있거나 브랜치 이름으로 보이지 않으면 실행하지 말고 브랜치 이름을 물어본다.

1. 새 세션에게 줄 작업 지시서를 쓴다. 이 대화를 처음 보는 사람이 그것만 읽고 바로 시작할 수 있어야 한다.
   "위에서 말한", "앞서 정한" 처럼 이 대화를 가리키는 표현은 쓰지 않고 내용을 직접 적는다.
   - 작업 디렉토리는 브랜치 `$0` 의 워크트리이고, 메인 체크아웃의 파일은 수정하지 않는다는 것
   - 목표와 배경 (왜 하는지)
   - 범위: 할 것과 하지 않기로 한 것
   - 설계 결정과 그 이유, 관련 파일·함수의 경로
   - 완료 조건과 확인 방법 (돌릴 테스트·명령)
   - 남은 질문 (스스로 정하지 말고 사용자에게 물을 것)
   - 첫 번째로 할 일
   - 사용자의 추가 지시 (인자 전체: `$ARGUMENTS`, 첫 단어는 브랜치 이름이다)
2. 그 지시서를 표준 입력으로 넘겨 Bash 로 한 번 실행한다. 지시서에 `WORKTREE_HANDOFF_EOF` 만 있는 줄은 넣지 않는다:
   ```
   worktree-handoff --fresh --prompt-file - -- '$0' <<'WORKTREE_HANDOFF_EOF'
   <1의 지시서>
   WORKTREE_HANDOFF_EOF
   ```
3. 실패하면 오류를 그대로 보여 주고 멈춘다. 성공하면 출력된 워크트리 경로와 윈도우를 한 줄로 알린다.
   그 뒤로 이 원본 세션에서는 그 워크트리의 파일을 편집하지 않는다.
